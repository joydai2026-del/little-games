# MVP plan: Caption Wars

JJ's WHAT (2026-09-07): "One photo drops, everyone captions; vote the winner." Web page, phone-friendly,
public URL. Humans and AI players mixed in the same round (AI players caption AND vote, never for
themselves; if JJ is alone the bots fill the table). Photo is a random internet photo, zero setup.

## Goal (the locked WHAT)
Open the link, type a name, get a 4-letter room code, friends join from their phones. Each round: a
photo appears, everyone (humans and bots) writes one caption within the timer, then all captions are
shown anonymously and everyone votes for one (not their own). Reveal shows who wrote what and who won
the round; points add up on a scoreboard; after N rounds the game names a champion. No accounts, no
ads, no tracking. Works with 1 human + bots, or 8 humans + 0 bots.

## Done tests (binary)
1. Phone opens the public URL, creates a room, a second device joins by code, both see the same photo
   at the same time.
2. One human + 2 bots play a full 3-round game start to finish; every bot caption is visibly about the
   photo (JJ eyeballs it); a winner is shown each round and a champion at the end.
3. Bots never block: with Workers AI failing (forced in a test), the round still ends on the timer.
4. A terminal agent (`node agent/play.mjs --room CODE --brain claude`) joins a live room and its
   captions and votes show up like any player's.
5. Deployed at a public workers.dev URL; `npm test` and `npm run typecheck` green on the deployed commit.

## Architecture (HOW, decided by Claude, Codex-reviewed)
| Concern | Choice | Why |
|---|---|---|
| Frontend | Vite + vanilla TypeScript SPA, hash router, no framework | same shape as the vocab game; phone-first CSS is simple |
| Hosting | One Cloudflare Worker: static assets + API, workers.dev | JJ is logged in to Cloudflare; wrangler 4.128.0 passed the safety scan 2026-09-02; free tier |
| Rooms | Durable Object per room (SQLite storage), polling with `version` + `nextPollMs` | one source of truth per room; polling is enough for 8 players; proven pattern today |
| AI players | Cloudflare Workers AI: vision model writes captions, text model votes | no external LLM key exists on this machine (verified 2026-09-07); Workers AI is free tier and always on |
| Photo | Worker fetches `https://loremflickr.com/{w}/{h}/{tags}` (redirects to a stable Flickr CDN URL); fallback `https://picsum.photos/seed/{n}/{w}/{h}` | no key; tags give funny subjects; the resolved URL is stored so all players and the vision model see the same bytes |
| Agent-native path | `agent/play.mjs`: a Node script that joins a room over the same HTTP API with a pluggable brain command (`claude -p`, `codex exec`, `grok -p`) | lets JJ's logged-in CLIs play from her Mac; same API as the browser |
| Tests | vitest on pure logic (room reducer, vote tally, phase transitions, caption validation) | fast, no browser |

## Data model (src/shared/types.ts, the contract)
```ts
export type Phase = 'lobby' | 'caption' | 'vote' | 'reveal' | 'done';
export interface RoomOptions { rounds: number; captionSeconds: number; voteSeconds: number; revealSeconds: number; botCount: number }
export interface Player { id: string; name: string; isBot: boolean; score: number; connected: boolean }
export interface Photo { url: string; source: 'loremflickr' | 'picsum'; credit?: string }
export interface Caption { id: string; playerId: string; text: string }
export interface RoundResult { round: number; photo: Photo; captions: Caption[]; votes: Record<string, string>; winnerCaptionIds: string[] }
export interface RoomState {
  code: string; version: number; phase: Phase; round: number; options: RoomOptions; hostId: string;
  players: Player[]; photo?: Photo; captions: Caption[]; votes: Record<string, string>;
  phaseEndsAt?: number; history: RoundResult[]; championIds?: string[]; nextPollMs: number;
}
```
Captions are returned to clients WITHOUT `playerId` during `vote`; the client only sees `playerId`
in `reveal` and later. The DO strips it, not the client.

## API contract (src/worker)
- `POST /api/rooms` `{ name, options? }` -> `{ code, playerId, state }` (creator is host; bots added at create)
- `POST /api/rooms/:code/join` `{ name }` -> `{ playerId, state }` (any phase; a mid-game joiner plays from the next round)
- `POST /api/rooms/:code/start` `{ playerId }` host only, lobby -> caption (fetches photo, schedules bots)
- `POST /api/rooms/:code/caption` `{ playerId, text }` caption phase only, one per player, first write wins, 1..captionMaxChars, trimmed
- `POST /api/rooms/:code/vote` `{ playerId, captionId }` vote phase only, not own caption, first write wins
- `POST /api/rooms/:code/next` `{ playerId }` host only, reveal -> caption (or done after the last round)
- `GET /api/rooms/:code?v=N&p=PLAYERID` -> `{ state }` or `{ unchanged: true, nextPollMs }`
- Errors: JSON `{ error: string }` with 4xx; unknown room 404.

Phase rules (all in the DO, server clock):
- `caption` ends when every eligible player has a caption OR `phaseEndsAt` passes (DO alarm). Then `vote`.
- `vote` ends when every eligible voter voted OR alarm. Eligible voter = anyone with a caption OR without
  one (everyone votes), but you cannot vote for your own. If fewer than 2 captions exist the round is void
  (no points) and goes to `reveal` with a "not enough captions" flag.
- Tally: points = votes received; every tied top caption wins; `reveal` lasts `revealSeconds` then auto
  advances (host `next` advances early). After round `rounds`, phase `done`, `championIds` = top score(s).
- `nextPollMs`: lobby 2000, caption/vote 1500, reveal 1500, done 0 (stop). Every mutation bumps `version`.
- State persists to DO SQLite storage after every mutation and is reloaded in the constructor.
  Room deleted by alarm `roomTtlHours` after creation.

Bots (src/worker/bots.ts):
- On entering `caption`, the DO kicks off bot work without blocking the request (`ctx.waitUntil` or an
  immediate alarm step); each bot: fetch photo bytes, call `VISION_MODEL` with its persona prompt, submit
  through the same caption path. On entering `vote`, each bot calls `TEXT_MODEL` with the anonymous
  caption list (excluding its own) and votes for one id; invalid model output = no vote.
- A bot that fails simply does not act; the phase ends on the timer. Bot failures are logged, never thrown
  to humans. Bot calls have a hard timeout (config, default 20s).
- Caption cleanup: strip quotes, cap length, one line.

## Client (src/client)
Screens: Home (name + Create / Join with code), Lobby (code big, player list with bot badge, host options
and Start), Caption (photo, countdown, one input, Send), Vote (photo small, shuffled anonymous captions as
big tap targets, own caption greyed and unvotable), Reveal (captions with author names and vote counts,
round winner banner, scoreboard), Done (champion, scoreboard, Play again = new room with same players'
names prefilled). Countdown is driven by `phaseEndsAt` minus a server/client clock offset measured on
each poll. Big type, high contrast, works one-handed on a phone. Copy-link button on the lobby
(`/#/room/CODE`). Player id is kept in `sessionStorage` per room so a reload rejoins.

## Agent path (agent/play.mjs)
`node agent/play.mjs --url https://... --room CODE --name "Claude" --brain claude|codex|grok`. Polls
the room, on `caption` downloads the photo and runs the brain command with the image and a persona prompt
(`claude -p` reads an image path; `codex exec -i <img>`; `grok -p`, text only if it cannot take images,
in which case it captions from the vision model's description obtained via `GET /api/rooms/:code/photo-description`,
builder decides whether that endpoint is worth adding or grok is text-only and captions blind, stated in the README).
On `vote` sends the caption list to the brain and votes. Exits when `done`.

## Amendments after Codex round 1 (2026-09-07, verdict FIX-FIRST; every MUST-FIX adopted, SHOULD-FIX and NITS adopted where noted)
These override anything above that conflicts. Full review: scratchpad `codex-plan-review.md` (session 2026-09-07).

1. **One alarm, one scheduler.** A Durable Object has ONE alarm. State carries `phaseEndsAt`, `expiresAt`, and
   `botJobs[]` (each with `dueAt`). After every mutation the DO sets the alarm to the EARLIEST of those. `alarm()`
   runs every due task (phase end, due bot jobs, expiry) then re-arms. Never overwrite the alarm for one purpose.
2. **Bot work is durable job state, not `waitUntil`.** On entering `caption` (and `vote`) the DO appends one job per
   bot `{ jobId, botId, round, phase, dueAt: now, deadline: now + BOT_TIMEOUT_MS, status }` and arms the alarm for now.
   The alarm handler runs due jobs: fetch stored photo bytes, call Workers AI with a hard timeout (`AbortSignal.timeout`),
   then RE-READ `{ phase, round, version }` and drop the result if the room moved on; otherwise submit through the
   same validated reducer path as a human. Jobs are idempotent (status `done` / `failed` recorded), never retried
   past `deadline`, and a failure is logged and ignored. Humans never wait on a bot.
3. **The Worker owns the photo bytes.** At round start the DO fetches the image ONCE with GET (never HEAD:
   loremflickr answers HEAD with a placeholder and picsum returns 405), follows redirects, and validates: status 200,
   `content-type: image/*`, byte cap `PHOTO_MAX_BYTES` (default 2 MB, enforced while reading), and that the final URL
   does not contain `defaultImage` (loremflickr's "no match" placeholder). Retry once with a different tag, then fall
   back to `https://picsum.photos/seed/<code>-<round>/<w>/<h>`. Bytes go into DO storage under `photo:<round>`;
   `photo` in state is `{ round, source, credit?, sha256, bytes }` metadata only. Clients load
   `GET /api/rooms/:code/photo/:round` (served from storage, `Cache-Control: private, max-age=3600`). Bots read the
   same bytes from storage. Only the newest 2 rounds of bytes are kept.
4. **AI preflight.** `POST /api/ai-smoke` guarded by a wrangler secret `SMOKE_TOKEN` (header `x-smoke-token`): sends
   the Meta license-acceptance prompt if the model requires it, runs a bundled fixture image through `VISION_MODEL`
   (fallback `VISION_MODEL_FALLBACK`), runs a JSON-mode vote through `TEXT_MODEL`, returns which model ids answered.
   `npm run ai:smoke` calls it against the deployed URL. Deploy gate: smoke must pass before JJ sees the link.
5. **Vote view is per requester.** During `vote` the reducer returns captions as `{ id, text, isOwn, canVote }` only.
   Authors (`playerId`) appear only from `reveal` on. Self-vote is also rejected server-side.
6. **Player secret.** Create/join return `{ playerId, playerSecret }`. Every request carries `x-player-id` and
   `x-player-secret`; the DO rejects a mismatch with 403. State returned to clients never includes secrets. The
   browser keeps both in `sessionStorage` per room code.
7. **Frozen round roster.** On entering `caption` the reducer sets `roundPlayerIds` (humans + bots present at that
   moment). Only those ids may caption or vote this round, and "everyone acted" means everyone in that list. Joiners
   during a round see the round as a spectator and enter the roster next round.
8. **Time is checked on every request.** Each GET/POST first runs `advanceIfDue(serverNow)`; the alarm is backup.
   Every response includes `serverTime` so the client computes a clock offset.
9. **No await gaps around mutations.** The DO loads state into memory once (constructor via `blockConcurrencyWhile`),
   every reducer call is synchronous, and the write to storage follows immediately. Anything that awaits (fetch, AI)
   happens outside the reducer and re-validates `{ phase, round, version }` before mutating.
10. **Text-only rendering.** Names and captions are rendered with `textContent` / DOM text nodes, never `innerHTML`.
    Server trims, collapses to one line, caps length (name 20, caption 120). Test: a caption `<img src=x onerror=alert(1)>`
    renders as literal text (client test or a reducer test on the sanitizer plus a grep gate: no `innerHTML` in `src/client`).
11. **Polling budget.** `nextPollMs`: lobby 3000, caption/vote 2000, reveal 2500, done 0. Client adds ±20% jitter and
    backs off to 10000 when the tab is hidden; `unchanged` responses cost nothing on the DO beyond the version compare.
12. **Machine-proven photo path.** vitest test of `bots.ts` with a fake `AI` binding and fake storage: the bytes the
    fake model receives hash to the fixture's sha256. Done test 2 keeps JJ's eyeball on top of that.

SHOULD-FIX adopted: reveal floor (host `next` allowed only after `REVEAL_MIN_MS`, default 3000); caption order for
voting is shuffled with a seed of `code + round` so every screen shows the same order; options are clamped
server-side by `normalizeOptions`; image byte cap enforced while streaming; bot voting uses JSON mode with a schema
and treats a "JSON Mode couldn't be met" error as no vote; room code collision handled (creation asks the DO, which
refuses if it already holds a room, then a new code is drawn, up to 5 tries); state persists `createdAt`, `expiresAt`,
`phaseStartedAt`, `roundPlayerIds`.
NITS adopted: `connected` replaced by `lastSeenAt` (display only, never affects eligibility); fallback vision model
is config and covered by the smoke test; in `agent/play.mjs` a brain that cannot take an image runs in a mode the
README labels DEGRADED (captions without seeing the photo); `claude -p` and `codex exec -i` see the image.

### Contract changes (supersede the data model and API above)
```ts
export interface Player { id: string; name: string; isBot: boolean; score: number; lastSeenAt: number }
export interface PhotoMeta { round: number; source: 'loremflickr' | 'picsum'; credit?: string; sha256: string; bytes: number }
export interface BotJob { jobId: string; botId: string; round: number; phase: 'caption' | 'vote'; dueAt: number; deadline: number; status: 'pending' | 'running' | 'done' | 'failed' }
export interface VoteCaption { id: string; text: string; isOwn: boolean; canVote: boolean }
export interface RoomState {
  code: string; version: number; phase: Phase; round: number; options: RoomOptions; hostId: string;
  players: Player[]; roundPlayerIds: string[]; photo?: PhotoMeta; captions: Caption[]; votes: Record<string, string>;
  createdAt: number; expiresAt: number; phaseStartedAt: number; phaseEndsAt?: number;
  botJobs: BotJob[]; history: RoundResult[]; championIds?: string[]; nextPollMs: number;
}
// Secrets live in a separate storage key (`secrets`: Record<playerId, secret>), never in RoomState.
// Client view: `publicView(state, viewerId, now)` returns RoomState minus botJobs, with captions replaced by
// VoteCaption[] during `vote`, only the viewer's own caption during `caption`, and serverTime added.
```
API: all mutating routes and the GET take headers `x-player-id` / `x-player-secret` (create is the exception).
Responses: `{ state, serverTime }` or `{ unchanged: true, nextPollMs, serverTime }`. New routes:
`GET /api/rooms/:code/photo/:round` (image bytes), `POST /api/ai-smoke` (secret-guarded).
